Анализ продаж розничной сети на датасете Global Superstore (~51 тыс. заказов, 2011–2014, источник — Kaggle). Задача — не прогноз, а практический бизнес-анализ: найти, где компания теряет деньги, и обосновать рекомендацию цифрами. Данные обработаны и проверены двумя независимыми способами — в Excel и в SQL — чтобы показать один и тот же результат, полученный разными инструментами.

Результат коротко

— Обработал и объединил 51 тыс. заказов из 3 источников в Excel (Power Query, Merge Queries) и продублировал в PostgreSQL (JOIN); нашёл и исправил ошибку данных (некорректный формат дат при импорте CSV).

— Построил дашборд с KPI и срезами в Excel; повторил ключевые агрегаты через SQL (GROUP BY, JOIN, CASE, подзапрос, оконная функция RANK) — результаты сошлись в обоих инструментах.

— Выявил и количественно обосновал причину убыточности категории Tables (скидки свыше 30-40%, повышенная доля возвратов), сформулировал рекомендацию.

Данные

Три исходные таблицы: Orders (заказы: дата, регион, категория/подкатегория товара, продажи, прибыль, скидка, способ доставки), Returns (какие заказы были возвращены), People (менеджер по региону).

Бизнес-вопросы
Как меняются продажи и прибыль по годам?
Какие категории/подкатегории самые прибыльные, а какие убыточны?
Как скидка влияет на прибыль?
Какой регион/сегмент даёт больше всего выручки и прибыли?
Какая доля заказов возвращается и в каких категориях возвратов больше?
Ключевые находки
Рост здоровый: продажи и прибыль стабильно растут 2011→2014 (+18%, +27%, +26% год к году).
Маржа стабильна (~11–12%) почти везде, кроме одной проблемной зоны.
Единственная убыточная подкатегория — Tables (прибыль −64 083 за весь период) при немаленьких продажах (757 042) — проблема не в спросе, а в марже.
Причина — избыточные скидки: средняя скидка у убыточных заказов ~45%, у прибыльных ~4,3%. Рекомендация: ограничить максимальную скидку или пересмотреть базовую цену для Tables.
Повышенные возвраты в тех же зонах: Tables (7,78%), Fasteners (7,31%), Appliances/Accessories (~7,1%) — совпадает с проблемной зоной по прибыли.

Оба вывода (по прибыли и по возвратам) независимо подтверждены и в Excel, и в SQL.

Пример SQL

-- Доля возвратов по категориям и подкатегориям

SELECT category, sub_category,
    count(*) AS count_orders,
    count(CASE WHEN returned = 'Yes' THEN 1 END) AS count_returned_orders,
    (count(CASE WHEN returned = 'Yes' THEN 1 END)::numeric
        / count(*)::numeric) * 100 AS share_order
FROM orders o
LEFT JOIN returns r ON r.order_id = o.order_id
GROUP BY category, sub_category
ORDER BY share_order DESC;

Исправление ошибок и багов

При загрузке дат в PostgreSQL обнаружился баг: часть заказов ошибочно попадала в 2015–2016 год вместо 2011–2014. Причина — несовпадение формата дат при импорте CSV (dd/MM/yyyy в файле против неверно настроенного парсера при импорте). Диагностировано через точечную сверку значений между Excel и SQL, исправлено настройкой формата в мастере импорта DBeaver.
